### 🔍 What I Learned

- **Interpreter Isolation:** Virtual environments isolate dependencies per project; VS Code/IDE must point to the specific `.venv/bin/python` interpreter.
- **Database Driver Layering:** SQLModel relies on SQLAlchemy, which requires a database driver (`psycopg`) to speak PostgreSQL's binary protocol over TCP.
- **FastAPI Lifecycle:** Dependencies using `yield` function as context managers, handling setup *before* route execution and cleanup *after* the HTTP response returns.


```

FastAPI Route ──> Depends(get_session) ──> SQLModel / SQLAlchemy ──> psycopg ──> PostgreSQL

```

- **`psycopg`**: Python ↔ PostgreSQL driver.
- **`engine`**: Manages connection infrastructure and connection pooling.
- **`session`**: Short-lived transactional scope for database operations.
- **`echo=True`**: Engine setting that logs generated raw SQL queries to terminal stdout.
- **`yield`**: Delivers a session instance per request and ensures clean resource teardown.

### ⭐ One Thing I Understand Better Now

> `create_engine` doesn't open an active database connection immediately—it acts as a connection pool factory. Active connections are checked out only when a `Session` executes a query and are returned to the pool when the session yields/closes.
